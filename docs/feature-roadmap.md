# 서버 관리 기능 확장

명령어는 한국어 Discord에서 한국어 로컬라이즈 이름으로 표시한다. Discord API 등록을 위해 영문 fallback 식별자는 유지한다.

Carl-bot의 공개 기능을 참고하여 Hawawa Dosiyo에 맞는 슬래시 명령어로 새롭게 구현한다.
Carl-bot 소스·설명 문구를 그대로 복제하거나 기존 명령어를 덮어쓰지 않는다.
아래는 기능군 단위의 진행표이며, 전체 명령어와 옵션을 대조한 호환성 목록은 아니다.

참고 문서:
- https://github.com/botlabs-gg/carlbot-docs/blob/master/docs/_sidebar.md
- https://github.com/botlabs-gg/carlbot-docs/blob/master/docs/utilities.md

## 현재 구현

- 기본: `/ping`, `/help`, `/serverinfo`
- 유틸리티: `/userinfo`, `/avatar`, `/roll`, `/vote`, `/poll`, `/randomteam`
- 관리: `/clear` (실행자와 봇 권한 검사)
- 운영: `/tag`, `/welcome`, `/autorole`, `/serverconfig`, `/suggest`
- 예약·역할: `/reminder`, `/rolepanel`, `/rolepaneldisable`
- 기간 역할·추첨·추천: `/temprole`, `/giveaway`, `/starboard`
- 활동·자동 관리: `/rank`, `/leaderboard`, `/automod`
- 추가 운영: `/modcase`, `/trigger`, `/embed`, `/greetingtemplate`, `/sticky`
- 확장 역할: `/roleautomation`, `/levelreward`
- 건의·게임·조회: `/suggestion`, `/coinflip`, `/rps`, `/members`
- 입력 구분자는 쉼표로 통일한다. 투표·건의·역할 패널·서버 이벤트 안내는 공개 게시하며, 나머지 명령 응답은 본인에게만 표시한다.

## 1차: 정보 조회 보강

- [x] `/userinfo`: 서버 표시 이름·가입일·역할 추가 (조회 가능한 서버 멤버 정보가 있을 때)
- [x] `/avatar`: 서버/계정 아바타 선택
- [x] `/charinfo`: Unicode 코드 포인트·이름·보이지 않는 문자 조회
- [x] `/permissions`: 현재 채널의 실행자·다른 멤버·봇 권한 조회
- [x] `/members`: Members Intent·완전한 캐시를 확인하고 계정 생성일·가입일 기준 조회
- [ ] 기타 유틸리티·게임: 공식 명령어별 필요성과 입력·출력 명세 대조

## 2차: 여러 서버를 위한 공통 기반

진행: 새 `data/hawawa-v3.db`에 서버별 설정·태그를 분리 저장한다. 기존 DB는 변경하지 않는다.
기본 자동 역할 1개와 고정 문구 입장 안내, 태그 저장·조회·목록·삭제를 구현했다.
입장 이벤트는 `ENABLE_MEMBER_EVENTS=true`와 Developer Portal 설정이 필요하다.
리마인더는 만료 작업 복구, 임시 전송 실패 재시도, 사용자·서버별 취소를 지원한다.
버튼 역할은 고정 custom_id와 서버·메시지별 DB 매핑으로 재시작 후 복구한다.
입퇴장·채널/역할 생성·삭제 로그, 건의 게시, 경험치·순위, Discord 기본 금칙어·멘션 차단 연계를 추가했다.
일반 역할 지연 지급·30일 재입장 복원, 안전한 고정 변수 템플릿, 반복 리마인더를 추가했다.
건의 투표·승인/반려, 레벨 보상, 재추첨과 하단 안내도 구현했다.

## 이번 구현의 제한

- 리마인더는 전송 직후 강제 종료 시 중복될 수 있다. 한 DB에는 봇 프로세스 하나만 실행한다.
- 버튼 역할은 일반 역할의 공개 지급/회수를 지원한다. `/temprole`은 만료 후 회수, `/roleautomation`은 지연 지급과 재입장 복원을 담당한다. 이모지 반응 역할·조건부 접근 제한은 미구현이다.
- 서버 로그는 입퇴장·채널/역할 생성·삭제이며, 메시지 본문과 감사 로그 행위자 기록은 미구현이다.
- 건의는 게시·찬반 투표·승인/반려를 지원한다. 투표는 사용자당 1개이며 변경·취소할 수 있다. 별도 스타보드는 공개 메시지 링크 게시와 개별 ⭐ 반응 수 갱신을 지원한다.
- 추첨은 참가·취소·자동/조기 마감·직전 당첨자 제외 재추첨과 저장된 결과 복구를 지원한다. 참가 조건·경품 지급은 미구현이며, 탈퇴자도 추첨에 포함된다.
- 기간 역할 만료와 추첨 마감은 봇 재시작 후 복구하지만, 한 DB에는 프로세스 하나만 실행한다.
- 스타보드는 본문을 복사하지 않으며, 전송/DB 기록 사이 종료 시 중복될 수 있다. 전체 반응 지우기·원본 삭제 동기화는 미구현이다.
- 자동 관리는 Discord 기본 금칙어/멘션 차단만 지원한다. Discord의 기본 예외·한도 정책을 따른다.
- 경험치는 기본 점수·분당 제한·순위와 일반 역할 보상을 지원한다. 보상은 다음 경험치 획득 시 반영하며 역할을 자동 회수하지 않는다.
- 자동 응답은 정확 일치·고정 변수 치환만 지원한다. 사용자 코드·임의 표현식 실행은 지원하지 않는다.
- 외부 피드는 사용자 요청으로 보류했다. 외부 계정·API 키는 사용하지 않는다.

- [x] 개발/운영 동기화 범위 명시, 기본 오류 안내, 도움말 분류·페이지 처리
- [x] 서버 ID를 기준으로 설정을 분리하는 DB 및 버전 1·미래 버전 거부
- [ ] 사용자·봇 권한, 역할 서열, 서버 소유자 보호 정책
- [ ] 예약 작업과 버튼 상호작용의 재시작 후 복구 및 중복 실행 방지
- [ ] 설정 초기화·삭제·보존 정책

## 이번 확장의 완료 항목

- [x] 경고 기록·조회·취소 (원본 및 처리자 보존)
- [x] 정확 일치 자동 응답, 고정 변수 템플릿, 안내 임베드
- [x] 입장 후 지연 역할, 30일 재입장 일반 역할 복원
- [x] 반복 리마인더, 직전 당첨자 제외 재추첨
- [x] 하단 안내, 환영·퇴장 문구 설정
- [x] 멤버 정렬, 동전 던지기, 가위바위보
- [x] 건의 찬반·취소 및 승인/반려
- [x] 레벨별 일반 역할 보상
- [x] `/help` 페이지 버튼과 파라미터 선택지 표시
- [x] 테스트 환경에서 서버 격리·관리 권한·역할 안전성·예약 복구 검증
- [ ] 실제 Discord 서버에서 각 새 명령어·권한 부족·재시작 복구 확인

보존: 설정·태그·경고 기록은 명시적 정리 전까지 유지한다. 역할 복원 기록과 추첨 참가 기록은
30일, 실패한 리마인더는 7일 후 작업자가 정리한다. 전체 데이터 일괄 삭제·내보내기는 미구현이다.
외부 연동은 2026-10-20 사용자 요청으로 보류했다.

## 기능군별 남은 범위 (아래 체크는 기능군 전체 완료 기준)

각 기능군은 명령어·옵션 목록 조사, 명세 작성, 구현, 권한/서버 격리 테스트를 거친다.

- [ ] Config: 서버별 기능 및 채널 설정
- [ ] Roles: 자동 역할, 반응/버튼 역할, 역할 관리
- [ ] Greetings: 입장·퇴장 안내
- [ ] Logging: 관리 작업 및 서버 이벤트 기록
- [ ] Moderation: 경고/처리 기록 및 필요한 제재 기능
- [ ] Automod: 조건·예외·제재 정책과 Discord 기본 자동 관리 연계
- [ ] Utilities: 리마인더, 키워드 알림, 추첨, 고정 안내
- [ ] Tags & Triggers: 저장 응답, 자동 응답, 안전한 템플릿 처리
- [ ] Suggestions / Starboard: 건의·추천 게시물과 중복 방지
- [ ] Levels: 경험치·순위와 서버별 정책
- [ ] Feeds / Notifications: 외부 서비스 알림, 인증·API 제한 검토
- [ ] Embeds: 안내 메시지 작성과 수정 권한
- [ ] Fun / Games: 개별 기능 선정 및 구현
- [ ] Personalization / Perks / Premium: Hawawa에 필요한 설정만 별도 설계

## 완료 기준

공식 문서의 개별 명령어 목록과 실제 구현을 대조하고, 동등 기능·대체 기능·제외 기능을
기록한 뒤에만 전체 범위 완료로 판단한다. 현재는 전체 Carl-bot 기능이 구현된 상태가 아니다.
외부 서비스, 유료 서비스 운영, 개인정보 보관 정책은 구현 전에 별도 검토한다.
기존 데이터 이전, 파일 삭제, 커밋·Push·병합에는 프로젝트 확인 절차를 적용한다.
