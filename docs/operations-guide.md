# 상세 운영 가이드

[프로젝트 소개·설치](../README.md) · [개발 진행표](feature-roadmap.md)

명령어 목록과 설치 방법은 루트 README에 정리되어 있습니다. 이 문서는 권한·입력 한도·데이터 보존·예약 복구 등 상세 동작을 설명합니다. 실제 옵션과 예시는 `/help command:명령어`에서도 확인할 수 있습니다.

## 공통 동작

- 선택지·참가자는 쉼표(`,`)로 구분하며 앞뒤 공백을 제거합니다. 빈 항목과 중복 항목은 거부합니다.
- 기본 응답은 실행자에게만 보입니다. 투표·건의·추첨·역할 패널·스타보드·안내는 채널에 게시하며, 리마인더는 DM으로 전송합니다.
- 일반 역할 자동화는 관리 권한이 없는 역할만 허용하고, 봇의 역할 서열을 검사합니다. 설정자는 지정할 역할보다 높아야 하며, 서버 소유자는 설정자 서열 검사에서 제외됩니다.
- 설정을 끄거나 삭제해도 기존 메시지·역할·점수·기록이 모두 삭제되지는 않습니다.
- 같은 DB에는 봇 프로세스를 하나만 실행합니다. 봇이 꺼진 동안 작업은 실행되지 않으며, 예약 종류에 따라 재시작 후 복구합니다.

## 기능별 실행 권한

| 명령어·작업 | 실행자 권한 |
| --- | --- |
| `/clear`, `/modcase`, `/embed`, `/sticky` | 메시지 관리 |
| `/members`, `/serverconfig`, `/welcome`, `/greetingtemplate` | 서버 관리 |
| `/tag` 저장·삭제, `/trigger`, `/suggestion`, `/giveaway`, `/starboard` | 서버 관리 |
| `/autorole`, `/rolepanel`, `/rolepaneldisable`, `/temprole`, `/roleautomation`, `/levelreward` | 역할 관리 |
| `/roleautomation action:restore` | 역할 관리 + 서버 관리 |
| `/automod` | 실행자·봇 모두 서버 관리 |

나머지 기본 조회·게임·투표·개인 알림과 태그 조회는 관리 권한을 요구하지 않습니다. 역할·추첨·건의의 공개 버튼도 일반 사용자가 이용할 수 있습니다. 봇에는 메시지 전송, 임베드, 투표 만들기, 역할 관리 등 각 작업에 필요한 권한이 별도로 있어야 합니다.

## 정보·게임·투표

- `/userinfo`와 `/avatar`의 `user`를 생략하면 본인을 대상으로 합니다. 서버 멤버 정보가 있으면 표시 이름·가입일·역할도 보여주며, `/avatar global_avatar:true`는 계정 아바타를 선택합니다.
- `/serverinfo`는 서버 이름·봇을 포함한 멤버 수·생성일을 표시합니다. `/permissions`는 주요 채널 권한만 보여주므로 역할 서열·스레드 상태 등으로 실제 작업이 제한될 수 있습니다.
- `/members`는 최대 25명을 계정 생성일 또는 서버 가입일 기준으로 정렬합니다. Members Intent와 완전한 멤버 캐시가 없으면 일부 정보로 정렬하지 않고 안내합니다.
- `/charinfo`는 최대 15개 Unicode 코드 포인트를 표시합니다. 결합 이모지는 여러 코드 포인트로 나뉠 수 있습니다.
- `/roll`: 2~1,000면 주사위 1~20개. 기본값은 6면 1개입니다.
- `/vote`: 선택지 2~20개, 각 100자 이내에서 하나를 무작위로 고릅니다.
- `/randomteam`: 참가자 2~40명, 이름당 40자 이내, 팀 2~10개. 팀별 인원 차이는 최대 1명입니다.
- `/poll`: 선택지 2~10개, 각 55자 이내, 질문 300자 이내, 1~168시간. `multiple:true`로 복수 선택을 허용합니다. Discord가 투표를 저장하므로 재시작 후에도 게시된 투표는 유지됩니다.

```text
/vote options:치킨, 피자
/randomteam participants:철수, 영희, 민수, 지수 teams:2
/poll question:주말 모임 options:토요일, 일요일 hours:24 multiple:true
```

## 태그·자동 응답·안내

```text
/tag action:set name:rules content:규칙을 읽어주세요
/tag action:show name:rules
/tag action:list
/tag action:remove name:rules
/trigger action:set keyword:안녕 response:{user}님, {server}에 오신 것을 환영합니다
/embed title:공지 text:{server}의 규칙을 확인해주세요
/sticky text:채팅 전 규칙을 확인해주세요
```

태그 이름은 1~32자, 저장 응답은 최대 1,800자입니다. 태그 목록은 최대 50개를 표시합니다.

자동 응답은 채팅 전체가 정확히 일치할 때 작동하며 대소문자·앞뒤 공백을 무시합니다. 서버당 최대 100개를 저장하고 `list`는 최대 15개를 표시합니다. 키워드는 100자, 응답은 1,500자 이내입니다. 채널당 10초의 대기 시간을 적용하며 봇·웹훅 메시지는 무시합니다. Message Content Intent를 켜야 합니다.

자동 응답·임베드·환영/퇴장 문구·하단 안내의 템플릿은 `{user}`와 `{server}`만 치환합니다. 임의 코드·표현식·속성 접근은 실행하지 않으며 멘션 알림을 보내지 않습니다. 태그 조회는 저장한 내용을 그대로 보여줍니다.

하단 안내는 일반 사용자 메시지에 반응해 최소 30초 간격으로 갱신합니다. 새 게시물을 저장한 뒤 이전 글을 삭제합니다. `disable:true`는 갱신만 중지하고 마지막 글을 남깁니다. 이전 글 삭제 실패나 전송·DB 기록 사이의 종료로 여러 글이 남을 수 있습니다. 하단 안내에는 Message Content Intent가 필요하지 않습니다.

## 환영·퇴장·기록

```text
/welcome channel:#입장안내
/greetingtemplate kind:welcome text:{server}에 오신 {user}님 환영합니다
/serverconfig feature:goodbye channel:#퇴장안내 enabled:true
/greetingtemplate kind:goodbye text:{user}님이 나갔습니다
/serverconfig feature:logs channel:#로그 enabled:true
```

입퇴장 안내와 멤버 로그에는 Members Intent가 필요합니다. 기본 문구 또는 설정한 문구를 사용합니다. 문구를 설정하는 것만으로 채널·이벤트 기능이 활성화되지는 않습니다.

`/welcome disable:true`로 환영 안내를 끄고, `/serverconfig`는 `enabled:false`로 해당 기능을 끕니다. 옵션을 생략하면 현재 설정을 조회합니다.

로그는 멤버 입퇴장과 채널·역할 생성/삭제를 기록합니다. 채널은 이름을, 멤버·역할은 ID를 표시합니다. 메시지 본문 보관이나 감사 로그에서 작업자를 추적하는 기능은 포함하지 않습니다. 봇이 오프라인인 동안의 이벤트는 재생하지 않습니다.

## 역할

| 기능 | 동작 |
| --- | --- |
| `/autorole role:@멤버` | 이후 입장하는 일반 멤버에게 역할 1개 지급. `disable:true`로 해제 |
| `/rolepanel role:@알림 title:알림 역할 선택` | 공개 역할 받기·해제 버튼. 멤버 캐시 대신 클릭 시 최신 멤버 정보 확인 |
| `/rolepaneldisable message_id:123` | 버튼을 비활성화. 기존 메시지·역할은 유지 |
| `/temprole member:@사용자 role:@체험 minutes:60` | 1분~30일 지급 후 회수. 예약된 역할에 다시 실행하면 만료 갱신 |
| `/roleautomation action:delay role:@멤버 minutes:60` | 앞으로 입장한 멤버에게 1분~30일 후 지급 |
| `/roleautomation action:restore enabled:true` | 이후 퇴장 멤버의 일반 역할을 보관하고 30일 내 재입장 시 복원 |

자동·지연·복원 역할과 멤버 입퇴장 처리에는 Members Intent가 필요하지만 버튼 클릭에는 필요하지 않습니다. 버튼 역할은 클릭할 때도 삭제·관리 권한·봇 서열을 다시 검사합니다.

기간 역할은 기존에 일반적으로 보유한 역할의 회수를 예약하지 않습니다. 예약 중인 역할을 수동으로 영구 역할로 전환하면 예정대로 회수될 수 있습니다. 회수 실패는 1분 후 재시도하며, 재시작 시 만료된 작업도 처리합니다.

지연 설정 변경은 기존 예약 시각을 바꾸지 않습니다. `action:remove`는 해당 역할의 설정과 대기 지급 작업을 취소하고, 이미 지급한 역할은 유지합니다. 목록은 최대 20개를 표시합니다.

복원 기록에서는 기간 역할·관리 권한 역할·관리형 역할을 제외합니다. 지급 시에도 안전성·봇 서열을 확인합니다. 복원 기능을 꺼도 이미 대기 중인 지급 작업은 실행될 수 있습니다. 만료된 복원 기록은 작업자가 정리합니다.

## 건의·경험치

```text
/serverconfig feature:suggestions channel:#건의 enabled:true
/suggest text:주말에 게임 모임을 열어요
/suggestion action:approve message_id:123 reason:반영 예정
/serverconfig feature:levels enabled:true
/rank
/leaderboard
/levelreward action:set level:5 role:@활동멤버
```

건의는 사용자·서버당 분당 1회 게시할 수 있으며 작성자가 대상 채널을 볼 수 있어야 합니다. 참가자는 찬성·반대·취소 버튼을 사용하고 사용자당 한 표를 변경할 수 있습니다. 승인은 `approve`, 반려는 `reject`, 조회는 `show`입니다. 처리 시 서버 닉네임과 사유를 표시하고 투표를 종료합니다. 버튼은 재시작 후에도 동작합니다.

경험치는 켜진 서버의 일반 사용자 메시지에 분당 10점을 지급하며 봇·웹훅·DM은 제외합니다. 100점당 1레벨이고, Message Content Intent는 필요하지 않습니다. `/leaderboard`는 상위 10명을 표시합니다. 기능을 꺼도 기존 점수는 남습니다.

레벨 보상은 다음 경험치 획득 시 적용하고, 실패하면 이후 획득 때 다시 확인합니다. 설정 제거는 기존 지급 역할을 회수하지 않으며 일괄 소급 지급은 지원하지 않습니다. 목록은 최대 25개입니다.

## 리마인더

```text
/reminder action:create minutes:30 text:약속 확인
/reminder action:create minutes:60 text:쉬는 시간 repeat_minutes:60
/reminder action:list
/reminder action:cancel reminder_id:123
```

예약·반복 간격은 1분~30일입니다. 사용자당 전체 서버를 합쳐 대기·전송 중 알림을 최대 25개 만들 수 있습니다. 현재 서버에서 본인이 만든 알림을 조회·취소하며 DM 수신을 허용해야 합니다.

15초마다 확인하고 재시작 시 기한이 지난 알림을 복구합니다. 반복은 성공적으로 전송한 시점부터 다시 예약하며 놓친 횟수를 몰아서 보내지 않습니다. 일시적 HTTP 실패는 최대 3회 시도하고, 실패 상태는 목록에 표시합니다. 실패 기록은 7일 후 작업자가 정리합니다.

전송 중인 알림은 취소·회수할 수 없습니다. DM 전송 직후 DB 처리 전에 강제 종료되면 중복될 수 있습니다. 반복 예약 생성 중 종료되면 일회성 예약만 남을 수 있으므로 생성 완료 응답을 확인하세요.

## 추첨·추천 게시판

```text
/giveaway action:create prize:참가자추첨 minutes:60 winners:1
/giveaway action:list
/giveaway action:end message_id:123
/giveaway action:reroll message_id:123
/starboard channel:#추천 minimum:3
```

추첨은 1분~30일, 당첨자 1~10명이며 버튼 참가·취소와 자동·조기 마감을 지원합니다. 목록은 진행 중인 최대 20개를 표시합니다. 결과를 먼저 저장한 뒤 원본 글을 수정하므로 결과 반영 실패 시 당첨자를 다시 뽑지 않습니다. 재시작 후 참가 버튼·예약을 복구하며, 작업 주기는 15초입니다.

30일 이내 재추첨은 직전 당첨자를 제외합니다. 참가 기록은 마감·재추첨 후 30일 보관하고 작업자가 정리하며 결과는 남습니다. 참가 후 탈퇴한 사용자도 대상입니다. 참가 자격 조건·경품 지급·참가자 내보내기는 지원하지 않습니다. 추첨 글에 접근·수정할 수 있는 봇 권한이 필요합니다.

스타보드는 `@everyone`에게 공개된 텍스트 채널의 일반 멤버 메시지 링크만 게시하며 본문·첨부파일을 복사하지 않습니다. 기본 별 기준은 3개이고 설정 범위는 1~100개입니다. 반응 개수에는 작성자·봇의 반응도 포함합니다.

개별 별 추가·제거 시 기존 추천 글의 개수를 갱신하고, 기준 미만이 되어도 글은 유지합니다. 전체 반응 삭제·원본 삭제는 자동 반영하지 않습니다. 채널 변경은 기존 글을 이동하지 않으며 `disable:true`는 갱신을 중지합니다. 게시 직후 DB 저장 전에 종료되면 중복될 수 있습니다.

## 메시지 정리·경고·AutoMod

```text
/clear count:10
/modcase action:warn member:@사용자 reason:규칙 위반
/modcase action:list member:@사용자
/modcase action:show case_id:123
/modcase action:revoke case_id:123
/automod kind:keywords action:set words:차단단어1, 차단단어2
/automod kind:mentions action:set mentions:5
```

`/clear`는 서버 텍스트 채널·스레드에서 명령어 이전의 최근 1~100개 메시지를 확인해 고정 글을 제외하고 삭제합니다. 실행자의 메시지 관리 권한, 봇의 채널 보기·기록 보기·메시지 관리 권한을 확인합니다. 실제 삭제 개수를 본인에게 알리며, 삭제는 되돌릴 수 없습니다. 오래된 글은 개별 삭제하므로 시간이 더 걸릴 수 있습니다.

경고는 본인·서버 소유자·설정자와 같거나 높은 역할의 멤버를 대상으로 할 수 없습니다. 서버 소유자는 대상의 역할 서열 검사에서 제외됩니다. 목록은 최근 10개이고, 취소해도 원본 사유·처리자와 취소자 ID를 보존합니다.

AutoMod는 Discord 기본 규칙을 생성·변경하며 `show`로 활성화 상태를 조회하고 `disable`로 Hawawa의 해당 규칙만 끕니다. 금칙어는 쉼표로 구분해 1~100개, 각 1~60자이며 설정하면 기존 목록을 대체합니다. 멘션 허용 수는 1~50개입니다. 다른 규칙은 유지하고, 예외·한도는 Discord의 정책과 서버 AutoMod 설정을 따릅니다. 기본 규칙은 봇이 꺼져도 작동합니다.

## 데이터·복구 범위

새 `data/hawawa-v3.db`는 서버 ID별로 설정·기록을 분리하고 사용자·메시지 ID로 예약·버튼을 구분합니다. 스키마 버전은 1이며, 테이블은 추가 생성하고 지원하지 않는 미래 버전은 거부합니다. 기존 `data/hawawa.db`를 변환하거나 이전하지 않습니다.

| 데이터 | 보존 |
| --- | --- |
| 설정·태그·경고·경험치·추첨 결과 등 | 명시적 정리 전까지 유지 |
| 실패 리마인더 | 7일 후 작업자가 정리 |
| 재입장 복원 역할 기록 | 30일 후 작업자가 정리 |
| 마감 추첨 참가 기록 | 마감·재추첨 후 30일 뒤 작업자가 정리 |

예약 회수·지급·추첨·리마인더는 재시작 시 처리하지만, 오프라인 중 입퇴장·자동 응답·반응 이벤트를 전부 복원하지는 않습니다. 같은 DB에는 프로세스를 하나만 실행하세요. 백업과 데이터 일괄 내보내기·삭제는 별도 운영 작업이며, 기존 데이터를 임의로 삭제하지 않습니다.
